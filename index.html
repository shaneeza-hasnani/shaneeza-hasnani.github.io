01

FRAUD DETECTION · SNOWFLAKE + SQL

Turning 6.3 million transactions into a review queue

A transparent way to help investigators focus on the transactions most worth reviewing.

The problem

Fraud represented only 0.13% of the synthetic PaySim data, so reviewing every unusual transaction would waste time.

What I did

I organized the data into a three-layer SQL pipeline and created understandable risk indicators based on account balances and transaction type.

The takeaway

The HIGH tier narrowed 6.3 million records to 5,145; 3,912 were labeled fraud, or 76% of the tier.

02

MARKET EVENT STUDY · PYTHON

What happens after corporate fraud becomes public?

A study of how stock prices changed around fraud-related disclosures.

The question

How much of a stock-price change reflects the disclosure itself rather than normal market movement?

What I did

I used a Fama-French three-factor model to estimate expected returns for 24 firms, then measured the difference around each disclosure.

The takeaway

The project documents a cumulative average abnormal return of -23.5% by Day +10, suggesting that reassessment continued after disclosure day.

View code and statistical tests on GitHub ↗
